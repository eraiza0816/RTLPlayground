# poly1305_mul の 8051 アセンブラ移植 — 調査資料

poly1305_mul (Poly1305 の h = h * r mod 2^130-5) の 8051 アセンブラ移植を
再検討するための資料。2026-08 に実機検証まで進めたが、sdld のバンク参照
解決の制約により実機で安定動作せず、C 版 (コミット 6f6623c) に復帰した。
将来の再挑戦に向けて、実装・検証結果・問題の根本原因・試行履歴を残す。

## ファイル

- `poly1305_mul.asm` — 8051 アセンブラ実装 (26bit リム乗算、BANK3 配置)
- `fix_bank_refs.py` — lcall/ljmp ターゲットを実機バンクマップ用に変換する
  ポストプロセススクリプト (未使用。調査用)

## 動機

C 版の poly1305_mul はブロックごとに SDCC の `__mullong` (32bit 乗算
ライブラリ) を 7 回呼び、再入スタック (SSEG 129B 上限) にフレームを積む。
アセンブラ化で:
- 再入スタック使用を 0 に (8bit MUL AB ベース)
- 実行速度の向上 (__mullong のソフトウェア乗算を排除)

## 実装内容 (poly1305_mul.asm)

- 26bit リム 5 本 (h[5], r[5]) の多倍長乗算
- 13bit 分割: `al*bl, al*bh+ah*bl, ah*bh` → 26bit の (lo, hi) ペア
- 8bit MUL AB のみ使用 (16bit x 16bit を 8bit 畳み込みで実装)
- 全 XDATA アクセスは DPTR + MOVX (後述の IDATA 問題を回避)
- 正規化: キャリー伝播 + mod 2^130-5 (×5 折り返し)

## 検証結果 (ucsim, フラット配置)

- RFC7539 §2.5.2 / RFC8439 §2.8.2 ベクタ: 全 PASS
- ランダム入力ストレステスト (ホスト C 版と比較): 2000 ケース PASS
- ヘルパー実行回数 (カウンタ計測): 期待値と完全一致
- mul16 単体 (0x3412 × 0x7856 = 0x1879EE0C): 一致

## 実機での問題 (PCB_K0402WS_V3)

症状: 正しい PSK の /enc がタグ不一致 (401)。診断コード入りビルドでは
クラッシュ。C 版 (6f6623c) は全テスト PASS するため、アセンブラ mul が原因。

### 根本原因: sdld のバンク参照解決

- SDCC の C コード: BANK3 内の関数呼び出し lcall は「バンク内オフセット」
  で解決される (例: 0x0000 → 物理 0x34000)。実機のバンクマップは
  オフセット方式のため正しく動作する。
- 手書きアセンブラのラベル参照 (lcall/ljmp): sdld は「物理 & 0xFFFF」
  で解決する (例: mul16 の物理 0x3A712 → ターゲット 0xA712)。実機では
  0x34000 + 0xA712 = 0x3EA12 (別のコード) を実行してしまう。
- ucsim はフラット配置 (64KB) のためこの問題が顕在化しない。

### 試行した対策 (いずれも解決せず)

1. **CSEG (非バンク領域) に配置**: 参照がフラット (物理 & 0xFFFF = 物理)
   で正しくなるが、CSEG が ~1,034B 不足 (mul は 1,963B、空き ~929B)。
   ヘルパー共通化は呼び出し側のオーバーヘッドが上回り逆効果。
2. **lcall ターゲットのポストプロセス変換** (fix_bank_refs.py):
   ビルド後に mul 内の lcall/ljmp ターゲットをオフセットに書き換え。
   - T - 0x4000 (SDCC の BANK3 ベース 0x34000 基準): 401
   - T - 0x8000 (imagebuilder の再配置 0x20000 基準): 401
   命令境界は 8051 オペコード長テーブルで追跡 (即値の誤検出は修正済み)。
   変換自体は正しく適用されたが、タグ不一致は解消しなかった。

## 将来の調査ポイント

1. **sdld のバンク参照解決**: アセンブラの参照を C と同じ「バンク内
   オフセット」で解決させる方法 (sdld のソース調査、または
   .rel の参照形式の差の解明)
2. **実機のバンクマップの正確な仕様**: RTL837x のバンク機構
   (PSBANK レジスタ、コード空間 X → フラッシュのマッピング) を
   データシートで確認
3. **CSEG 容量の確保**: mul を ~929B 以下に収めるためのコードサイズ
   削減 (add_from_*/mul5_* の再設計、ループ化) または CSEG の
   既存コードを BANK へ移動
4. **ホスト側の相互検証**: 実機のバンクマップを再現する ucsim 拡張
   (バンク切り替えのエミュレーション) ができれば、実機なしで検証可能

## 途中で発見・解決した問題 (実装の教訓)

1. **r0/r1 への 16bit XDATA アドレス保持**: 8bit レジスタに切捨てられ、
   実機でクラッシュ (ucsim では XSEG が低アドレスで偶然動作)。DPTR +
   MOVX に全面書き換え。
2. **直接シンボル参照 (mov a, _sym 等)**: sdas8051 は「direct アドレッシ
   ング」(E5/F5/85) に変換し、IDATA をアクセスする (XDATA の下位 8bit
   に切捨て)。ハーネスでは IDATA が空きで偶然動作。全アクセスを
   DPTR + MOVX に書き換え。.lst で `E5*/F5*/85*` が無いことを確認。
3. **lcall の即値誤検出**: 変換スクリプトが lcall ターゲット内のバイト
   (0x12 等) を命令と誤検出。8051 オペコード長テーブルで命令境界を追跡。
4. **実機の XDATA 初期化**: XINIT セグメントはほぼ空 (20B) だが、
   `__mcs51_genXINIT` が XSEG 全体 (0x0001〜) を 0 埋めする。
   ブロックスコープ static も起動時に 0 になる。
5. **PSK 未設定プローブの後遺症**: /enc の PSK 未設定パスに aead_test
   診断をフックすると、その後の初回 /enc が 401 になる (診断コードの
   static が本番の状態を汚す)。本番から診断コードを除去済み。

## 実機の確認に使った診断手法 (再挑戦時に有用)

- mul16 冒頭にマーカー書き込み → HTTP 応答で確認 (ヘルパー実行の証明)
- 各ヘルパーの実行回数カウンタ (専用 XDATA、aead_test の冒頭でクリア)
- mul 前後の h[0] をアセンブラ内で保存 (SDCC の最適化で C 側の読みが
  信用できないため、アセンブラ内保存が確実)
- poly1305_blocks の m の内容・ctx アドレスを保存
